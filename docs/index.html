Overview

한눈에 보기

"ChatGPT 같은 챗봇을 직접 만들되, 단순 데모가 아니라 실제 서비스에 필요한 레이어(인증·권한·사용량 관리·운영·보안·테스트)를 갖춘다"를 목표로 한 풀스택 프로젝트입니다.

🎯

무엇을 만들었나

HuggingFace Router API로 여러 모델을 선택·전환하며 멀티턴 대화하는 챗봇. 대화는 DB에 저장되어 맥락이 이어지고, 응답은 토큰 단위로 실시간 스트리밍됩니다.

🧩

맡은 역할

기획부터 프론트엔드(React), 백엔드(FastAPI), DB 설계(MySQL), 인프라(Docker), 테스트, 보안까지 1인 풀스택으로 전 영역을 설계·구현했습니다.

⚙️

왜 의미 있나

LLM 연동(스트리밍·멀티턴·폴백), 상태 관리, 인증/권한 모델, 집계 쿼리, 컨테이너 오케스트레이션 등 실서비스에 필요한 문제들을 폭넓게 다뤘습니다.

Features

핵심 기능

사용자 경험과 운영 양쪽을 모두 고려해 기능을 설계했습니다.

⚡

실시간 스트리밍 응답

SSE 기반으로 모델의 토큰을 받는 즉시 화면에 타이핑하듯 출력. 긴 응답도 기다림 없이 자연스럽게.

🧠

멀티턴 맥락 기억

대화 기록을 DB에 저장하고 최근 N개를 모델에 함께 전달해 맥락을 유지. 토큰 절약을 위한 윈도잉 적용.

🔀

모델 선택 · 자동 폴백

HF Router의 실시간 가용 모델 목록을 검색 모달로 제공. 요청 모델이 죽어 있으면 살아있는 모델로 폴백.

🔐

인증 · 가입 승인제

bcrypt 해싱 + JWT 토큰. 가입은 '승인 대기' 상태로 시작하고, 관리자가 승인해야 로그인 가능.

🛠️

관리자 콘솔

사용자 승인/거부/권한 변경/삭제. 승인 대기자를 상단에 정렬해 운영 효율을 높임.

📊

토큰 사용량 대시보드

일별·모델별·사용자별 토큰 사용량을 집계해 차트로 시각화. 개인용/관리자용 뷰 분리.

📝

마크다운 · 코드 하이라이트

봇 응답을 표·목록·코드블록까지 렌더링. 코드 문법 하이라이트와 원클릭 복사 지원.

🔄

응답 재생성 · 자동 제목

마음에 안 드는 답변은 같은 질문으로 재생성. 첫 메시지로 대화 제목을 LLM이 자동 생성.

📱

모바일 반응형 · 단축키

햄버거 드로어 사이드바, 여러 줄 입력창, ⌘/Ctrl+Enter 전송 등 데스크톱·모바일 모두 최적화.

메시지 전송 → 스트리밍 흐름

1사용자 메시지 저장 + 대화방 확보(없으면 생성)
2최근 N개 + system 프롬프트로 맥락 구성
3HF에 stream 요청, 대화 ID를 응답 헤더로 먼저 전달
4토큰(delta)을 받는 즉시 프론트로 흘려보냄
5스트림 종료 후 전체 응답 저장 + 토큰 사용량 적재
Engineering Deep-dive

주요 기술적 도전과 결정

단순 구현을 넘어, "왜 이렇게 했는가"를 고민한 지점들입니다.

문제

응답이 끝나야 화면에 뜨면 체감이 느리다

HF의 stream: true + SSE를 httpx.stream으로 받아 토큰 단위로 프론트에 흘려보내고, 프론트는 ReadableStream 리더로 마지막 말풍선에 실시간 append. 스트림이 끝나면 한 번에 DB에 저장하고 토큰 사용량을 적재해 UX와 일관성을 모두 확보했습니다.

문제

대화가 길어질수록 토큰(비용)이 폭증한다

전체 히스토리를 매번 보내는 대신, system 프롬프트는 항상 유지하고 그 외 메시지는 최근 N개만 모델에 전달하는 윈도잉을 적용. DB엔 전체가 남아 화면/기록엔 영향이 없고, 모델에 보내는 입력만 절약합니다.

문제

모델 provider가 수시로 죽고 바뀐다

드롭다운을 하드코딩하지 않고 Router의 실시간 가용 목록에서 텍스트 채팅 모델만 필터링(10분 캐싱). 요청 모델이 사용 불가면 살아있는 기본 모델로 자동 폴백하고, HF 에러는 사용자 친화적 한국어로 변환합니다.

문제

"내 데이터"가 남에게 보이면 안 된다

모든 대화 조회/수정/삭제에서 소유권을 검증하고, 남의 리소스는 존재 자체를 숨기기 위해 403 대신 404로 응답. 관리자 전용 API는 의존성 주입(Depends)으로 일괄 보호했습니다.

문제

운영 배포 시 보안 사고를 코드로 막고 싶다

운영 모드에서 JWT_SECRET이 기본값/빈값이면 부팅 자체를 거부(토큰 위조 방지), Pydantic으로 입력 길이·형식을 검증, 공통 보안 응답 헤더와 환경변수 기반 CORS를 적용했습니다.

문제

리뷰어가 5분 안에 실행할 수 있어야 한다

docker compose up 한 번으로 프론트·백·DB가 기동되도록 구성. DB가 실제로 준비된 뒤 백엔드가 뜨도록 TCP 헬스체크로 마이그레이션 레이스를 차단하고, 데이터는 named volume에 영속화했습니다.

Quick Start

실행 방법

단 두 줄로 전체 스택이 기동됩니다.

# 1) 환경변수 준비 (HF 토큰 · JWT 비밀키 · 관리자 이메일 등)
cp .env.example .env   # 값 채우기

# 2) 풀스택 기동 (프론트 + 백엔드 + MySQL)
docker compose up -d --build

# → 브라우저에서 http://localhost:8080 접속

# (참고) 백엔드 테스트 실행
cd backend && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/pytest
